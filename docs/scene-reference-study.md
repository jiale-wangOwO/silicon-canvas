# 用途决定构图：官方芯片图与论文图研究

研究日期：2026-10-11。本次直接查看了以下官方原图、原论文图或 PDF 页面的渲染，观察的是信息选择和构图；本文的产品规则是 Silicon Canvas 的设计判断，并非原作者制定的标准。图中芯片数量、性能、容量和连接只属于对应来源，不能迁移成用户芯片的事实。

同一产品的不同图已经说明：商业概念、完整系统与局部技术图需要不同的信息组织。NVIDIA Blackwell [官方商业页面](https://www.nvidia.com/en-gb/data-center/technologies/blackwell-architecture/)中的 NVLink 和生成式 AI 图标则使用几乎无字的符号来解释单个卖点；这种符号适合作为辅助元素，不能取代完整芯片架构。

## 四个用途配置

用途与图的技术类型、配色应分别处理。“数据流”描述图要解释的技术关系，“商业展示”描述给谁看和用于什么场合；同一个数据流也可能需要商业概念或技术机制的不同构图。自然语言中已有 BP、融资、产品介绍、白皮书、设计评审或机制讲解意图时，应直接使用该意图，并允许手动调整。

| 用途 | 读者首先需要理解 | 主图范围与粒度 | 构图与视觉语言 | 标签与连接策略 |
| --- | --- | --- | --- | --- |
| 商业展示 / BP 概念 | 这是什么芯片系统、如何工作、与外界如何联系 | 保留完整系统；合并为少量功能域；内部实现细节转到辅助材料 | 整个系统为视觉主体，外围输入/输出有清晰方向；可以有克制的层次和图形化接口；大片留白 | 功能短名和已提供的价值说明；只画可解释系统故事的关系，不显示寄存器、队列或内部信号网络 |
| 系统架构 / 产品总览 | 计算、存储、互联和对外接口如何组成一个整体 | 完整边界与主要子系统；重复模块使用代表和已知数量 | 计算阵列、存储条带、互联骨架、外围接口各有角色；平面关系优先，最多两层可见层级 | 系统级接口与共享关系；没有事实依据时不添加总线、连线、数量、带宽和一致性 |
| 技术机制 / 论文评审 | 一个关键设计如何实现，为什么成立 | 围绕目标机制裁剪范围；局部可展开，源规格保全 | 角色相关形状、规则阵列、代表单元展开、明确端口；紧凑白底与少量强调色 | 需要精确信号、读写方向、条件和线型区分；细节超过一幅图承载时拆分 |
| 数据流 / 工作原理讲解 | 数据经过哪些阶段、在哪里复用或产生结果 | 选择一条主流程或一种操作数关系；必要时对齐小图 | 横向阶段、垂直轨道、张量 tile 或空间网格根据语义选择；顺序与方向清楚 | 操作数类型有稳定编码；复用、广播、归约与回写不能降格成通用流程箭头 |

这是密度、范围、形状、层级、布局和标注的变化。颜色主题只处理前景、背景和强调色；它不能负责系统语义的筛选。

## 编译与检查原则

1. 先识别解释目标与完整系统边界，再选择可见粒度，随后做布局，最后应用颜色。不能先摆一组卡片再补意义。
2. 完整系统描述用于商业/总览时，计算、存储和外部接口必须在同一主图中合理呈现。不能因为局部机制最容易排版就默认只画该局部。
3. 简化是把事实映射到有意义的宏功能区域，不是静默丢弃源规格。被收起的节点和边应有可追溯记录；必要技术事实保留在独立附图。
4. “突出优势”只能使用用户提供的能力与已核实数据。未知性能、成本、良率、工艺、芯粒数量、封装结构与连接不应自动填成产品承诺。
5. 每幅图只承担一个主要解释目标。先检查主体、范围、阅读顺序、重复资源、共享结构和片外边界，再检查字距、配色和装饰。
6. Image Gen 仍可能产生标签和技术关系错误；结构底稿、源规格、提示词与图后审核应共同使用。用途配置提高约束清晰度，不能宣称它已证明任意模型都能得到可发表成图。

## 常见失败

- 四种预设只替换颜色，节点和连线保持完全相同。
- 商业图保留全部内部队列、仲裁、寄存器和控制线；读者找不到芯片整体。
- 每个模块都画成同样大小的方卡；缓存、计算、共享资源与接口无法区分。
- 用发光芯片、假封装或大标题替代真实系统关系；看起来像海报，却解释不了系统。
- 为整齐而添加一个不存在的 NoC/Fabric，或把所有模块强制排成单链。
- 将论文总览图与详细机制图的粒度混在一幅主图中；代表单元展开也没有明确归属。
- 一次把多种数据复用关系画在同一网格上，靠增加颜色和更多图例补救拥挤。
