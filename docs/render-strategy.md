# 渲染表达策略

2026-10-18，内部契约 `RENDER3`。本轮改进从 NVIDIA、AMD 官网的真实产品图片中提取可迁移的构图经验，再写入共享编译核心；不是把厂商原图作为每次 Image Gen 的隐式输入。

研究来源与具体观察见 [NVIDIA 产品图研究](nvidia-render-study-20261018.md)和 [AMD 产品图研究](amd-render-study-20261018.md)。八张原图保存在被忽略的本地参考库，公共代码与 Web 只含官方来源链接、自有规则和本工具的实际生成图片。

## 主体先于装饰

`render_strategy.subject_plan` 根据用户要展示的完整对象、源中的设备角色和所有权，区分封装、裸片、板卡、多设备系统、服务器、机柜与晶圆。提到包内裸片不等于要求整张图变为裸片；引用“芯片发布会风格”不等于让多设备系统变成一颗芯片。明确的局部特写仍能选择部件。

`scene_profiles` 独立决定表现媒介。普通存储层级或逻辑概念图不会仅因“概念”一词变成产品渲染。自然的产品、技术和系统插图表达也不再只能靠固定的少数关键词进入空间插画流程。已有项目、手动设置和行为记法的兼容边界保持。

## 镜头与信息选择

机柜侧重竖向轮廓、正面层次和窄侧面；板卡要露出足够的板面与主要器件；服务器保留整机尺度；多设备系统使用共同镜头与尺度，把实际同级节点和共享资源作为独立主体，而非贴在芯片盖板上。

完整产品、逻辑功能覆盖、装配与局部剖切继续分开。多设备系统和封装装配不再继承把整个根容器折成一个功能清单的策略；各个源对象、所有权和选中连接保留在可见投影中。仅修改背景、镜头或材质不会自动把 hero 改成装配解释。

同级对象保持一致的材质和强调色。用表面粗糙度、明暗和接触阴影区分层次，避免每个模块换颜色、描发光边或堆金色饰边。默认不额外印上口号、应用场景清单或“Functional concept”徽章。板卡允许少量无标签的通用被动件、紧固件与表面细节作概念外观，但不能借此增加主要计算/存储对象、接口家族、型号或制造参数。

## 无字不等于空壳

无文字模式统一关闭排版指令，源对象名称只用于约束形体、数量和归属。系统 hero 仍保留真实 peer、hub 和支持对象；明确给定的物理部件数量不会因为取消标签而消失。产品外观未知的部分仍是可调整的概念表现，不升级成电路或 BOM 事实。

## 实际检查与边界

原始[光互连封装](../web/assets/render-study-20261018/01-optical-package.png)、[推理系统](../web/assets/render-study-20261018/02-inference-system.png)和[无字板卡](../web/assets/render-study-20261018/03-accelerator-board.png)保留当次工具提示词与源规格。它们经真实 STDIO MCP 与内置 Image Gen 生成，没有厂商参考图输入或额外美化提示词。主页的封装与板卡版本随后通过 Image Gen 添加 Silicon Canvas 品牌，属于编辑衍生图，原图和编辑记录分开保留。

主体与尺度的改善在实际图中可见。推理节点已从同一芯片表面回到四个独立设备；板卡和机柜分别形成自己的完整轮廓。仍有生成器偏差：无方向关联会被画成发光的双向箭头，光互连图会增添多条光路与具象端口，未知微小表面细节也可能表现为类丝印纹理。

所保留图片的提示词、源规格、首轮 PNG 和生成/审查记录位于对应资源目录。首图生成后，代码审计又补齐了无字系统对象保留、包含关系词序、风格修饰与仅背景反馈等通用边界；没有覆盖首图。历史记录中的版本与测试范围只对应当时的检查。当前验证方法见[验证说明](validation.md)；编译契约检查不能替代实际像素审查，也不能证明已经稳定达到所有厂商产品图的水平。
