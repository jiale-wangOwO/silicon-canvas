# 可迁移的技术图设计方法

研究日期：2026-10-12。目标是让不同芯片结构、算法、数据路径和产品说明都得到合适的表达。以下研究提供设计依据与可检查的机制；它不构成任意 Image Gen 输出已达到出版要求的证明。原论文和官网图例只保存在被忽略的 `.local/visual-research/`，发行包不增加第三方原图。

## 将审美变成内部设计决策

一个好的结果首先让读者知道应该看哪里、哪些东西属于一起，以及下一步该跟随哪条关系。颜色、质感和字体需加强这一结构。下面的流程是本项目依据研究提出的实现方向，内部使用即可，不应把它变成用户必须填写的分类表。

1. **推断阅读任务。** 从自然描述、用途和最新反馈中选择主要任务：了解整体、追踪一条路径、比较方案、定位资源、理解状态演化或识别产品。允许同时存在一个次任务。原输入不足时给出合理参考设计与明确来源；不要要求用户先学会图形分类。
2. **建立声明边界。** 区分逻辑归属、计算依赖、物理连接、真实时间和定量比例。参考图只能提供表达方式。图中的位置、面积、颜色、框与箭头不能悄悄增加本次设计没有的事实。
3. **选可组合的表达语法。** 根据数据与关系采用层级、依赖流、资源路径、状态图、共同时间轴、拓扑或有标注的产品主体。一个系统可用整体层级配一个数据路径细节；不同面板须说明各自在回答什么问题。
4. **选择可见范围。** 保存完整来源，依据阅读任务确定本图的主角、关键关系和上下文。若必须保留的信息过多，按有意义的边界拆解。概览和细节中的同一资源保持同一身份，重复绘制不代表复制硬件。
5. **生成有理由的构图。** 构图由源结构得出：同行代表等价角色，邻近代表局部关系，框表示确切共同范围，长轨表示持续状态，共同轴表示共同时间。让关系需要的走廊先占空间，再安排标签与对象。
6. **确定视觉字典。** 为这份源选择统一的节点、算子、数据对象、存储和外部角色样式。相同含义保持相同图形；不同形状、线型和颜色各有解释。不能用颜色同时编码模块类型、执行阶段与迭代编号。
7. **按目的地设置文字尺度。** 单栏、跨栏、幻灯片和封面可以有不同字号、密度与纵横比。将主标题、对象名、必要参数和辅助说明分级；可移入图注的是背景解释，不能把关键条件和数值移出其实际对象。
8. **检查预期读法。** 让检查记录直接回答读者问题，例如“这个结果从哪里来”“这条反馈回到什么状态”“哪个模块是共享的”。源关系核对、底稿几何检查和真实位图目视检查各保留结论。

## 可执行的视觉规则

| 设计机制 | 实现方向 | 可验证的验收 |
| --- | --- | --- |
| 视觉主次 | 定义主要对象/路径、相关上下文和辅助说明的层级；主要内容获得足够面积，支持内容降低填色和文字重量 | 将实际图缩到使用尺寸，能指出主要输入、输出或主体；标题、图例或支持框没有抢过主内容。缩略图观察记录事实，不用一句“有高级感”打分 |
| 接近与分组 | 成员内距小于组间距；确有归属才使用边界；控制框、驻留框、迭代框注明含义 | 每个框的成员集合与源完全匹配；共有资源不被某个私有边界包住；未归属的输出不进入循环框 |
| 对齐与节奏 | 对等对象共用基线、尺度和间距；同行/同列有可解释的共同角色 | 等价通路可沿同方向读；对比面板相同对象对齐；不用把不同含义或长短文本硬压成相同卡片 |
| 连线连续性 | 主路径少转折；旁路、返回和控制各有空间；箭头端点和必要标签留出位置 | 逐条追踪关键关系，端点唯一；穿过无关节点、假汇合和含糊交叉为失败；不能为减少线条而合并不同语义 |
| 文字与背景 | 对象名称短且稳定，必要数学式和数值准确；文字放在安静区域；减少重复标签和冗长框内说明 | 实际位图在目的地尺寸上无截字、重叠、漏字；给定条件/数字/轴/转置仍可读；检查提示词字号并不等于检查生成像素 |
| 颜色与形状 | 颜色选择服务于当前任务；深色文字、语义线型和形状共同承载含义 | 灰度或色觉模拟后核心关系仍可理解；重要线条与背景有足够对比；填色类别有稳定定义。固定“最多三色”只是起点，并非语义定律 |
| 留白与密度 | 内部留白用于文字、端口和走廊；整体空间用于主要内容；真正拥挤时调整布局或拆图 | 留白有用途，内容没有挤在角落；增加画布不能只增大标题与空区；拆图后的公共上下文不丢失 |
| 物理和示意深度 | 张量轴、特征分辨率、装配层次或产品表面可使用简洁深度；文字与路径仍优先清楚 | 深度确实解释形状或装配，且不掩盖标签；纯逻辑区不暗示实际 die/chiplet 数与面积；单镜头/投影保持一致 |

这里没有万能布局。共用总线的结构需要稳定的共享带，残差需要旁路，状态递推需要 old/update/new，网状拓扑需要实际邻接关系。把它们全部改成横向流程框会损坏信息。

## 各种图应回答的不同问题

| 内容 | 主要阅读问题与表达 | 必须检查的技术含义 | 不得借参考图补入的事实 |
| --- | --- | --- | --- |
| 系统/微架构 | 组成、归属、共享资源和外部接口；层级边界、对等区域、必要的局部细节 | 私有/共享、实例身份、外部资源在正确边界外、接口端点 | 核数、cache 容量、精确面积、功能等价或一致性协议 |
| 硬件数据路径 | payload 从哪里读出、经过哪些资源、何处汇合并写回；沿真实主路径组织资源与端口 | 同一存储返回、方向、读写选择、控制与数据区别、多输入/输出 | 位宽、lane 数、额外 buffer、DMA、旁路或握手保证 |
| 数学/算法数据流 | 值经过什么变换、操作数如何合流、哪些状态跨迭代保留；数据与算子不同图形，可用形状表达真实张量 | 操作类型、输入支路、残差端点、形状变化、axis、转置、old/new 状态 | 缺失的张量尺寸、sum/concat、tile 个数、SRAM/HBM 或硬件调度 |
| 条件过程与 FSM | 什么条件触发下一动作/状态、如何保持或恢复；明确谓词和外侧返回 | 分支条件、自环、reset、优先级、默认保持、终点 | 与行为不符的 Yes/No、默认状态、必然退出或吞吐量 |
| 时序/协议/调度 | 各参与者何时行动，哪些事件对齐或重叠；共用时间轴、固定资源/信号行 | 源事件位置、周期、有效窗口、采样沿、消息方向 | 仅从 DAG 推出的周期、耗时宽度、带宽、stall 或重叠 |
| 存储层级/互联拓扑 | 谁访问哪个层级，或谁与谁物理相连；分层和拓扑分别采用对应语法 | 邻接、层级、端口归属、访问关系与物理连接差别 | 自动全连接、router 格数、coherence、链路宽度与延迟 |
| 商业展示/解释性渲染 | 产品是什么、提供何种能力、处于哪个系统上下文；主对象、功能层或稀疏引线 | 能力源成员、外围角色、物理声明范围、相机与装配一致 | BOM、真实 package/工艺、应用行业、logo、工艺节点或性能数字 |
| 方案比较 | 两种机制的差别在哪里；共同坐标、同一对象字典、相同缩放，差异突出 | 公共部分一致，真正差异可定位；每个方案源完整 | 为使差距更显著而换尺度、删路径、改颜色含义或改参数 |

形态的选择可以灵活，声明的来源必须稳定。模糊输入仍能生成一份有用的参考设计，但假设不应被藏成已证实的产品事实。

## 从 0.5.1 发现的冲突与本轮处理

以下是研究开始时检查 0.5.1 源码与现有验证文档的观察。0.6.0 已增加共享设计计划、源结构支持的重复表示、精确行为语法、真实信息负担记录和独立控制附件；算法也保留了有意义的张量深度与源范围。大型算法分解、任意稠密状态/拓扑的布局能力和不同目的地字号验证仍需要继续扩大实测，不能把这些观察删掉后宣称已全面解决。

- `algorithm_flow.py:compile_figure` 把所有算法限定为无深度张量和无广域围框。现有论文研究却明确使用特征图厚度/形状、驻留区、堆叠括号和迭代范围。应禁止无意义装饰及错误范围，保留有源语义的形状和边界选择。
- 算法主图采用全部源节点与依赖的恒等投影。对小图很好，对大型模型/长迭代可能形成文字与连线堆叠。完整源保存与当前主图可见范围应分别记录；有理由的分解要保持可追溯性。
- 默认 `160 mm / 9 pt / 8.5 pt` 是一个文档预设。单栏、手机、幻灯片和商业封面需要不同预算；产品不能只在全屏样张上证明可读。
- `composition.PATTERNS` 有正确的高层类别指导，但类别本身不足以选择所有构图。同一架构可能要表达拥有关系、数据移动、部署或局部比较；还需由主要阅读任务和实际源结构决定。
- `bounded-flow-validation.md` 描述的 8 个资源 / 12 条关系门槛修复了一个小图默认折叠问题，但数量不是复杂度的全部。五个节点可能有密集多端口反馈；九个线性节点也可能清楚。应同时检查标签长度、扇入/扇出、分支、环、边界和必须显示的内容。
- 现有验证文档已经区分编译、跨运行时和位图审查，这是应保留的优点。后续不得因更多软件测试通过就把“图片未审查”改成“所有场景已出版级”。

## 用广泛案例验证迁移能力

真实改进需要覆盖结构差异，而不仅是增加几个好看的 SoC 示例。建议保存原创挑战集合，分别包括短链、多输入合流、残差/门控、长跳连、持续状态、嵌套归属、高扇入共享资源、稠密互联、条件分支、自环恢复、共同时间轴以及产品解释。每类包括常规、复杂和信息不完整输入。案例名称与具体芯片品牌不参与策略判断。

验收分三个层次，拒绝技术错误不能被其他项平均掩盖：

1. **来源与规划。** 每个必要对象、条件、数值和关系有来源；可见、附图和 deferred 范围可追溯；没有无依据的数量、连接、动作或时间。用程序验证可检查的集合、端点、身份和导出契约。
2. **真实图片阅读。** 使用工具正常输出的提示词生成；独立读者在未看描述时回答该图的主要问题，再逐条检查关键端点、范围和文字。保存原图与失败项；小样本不报告虚构的成功率。
3. **目的地与稳定性。** 按实际使用尺寸看图，包括缩减栏宽与幻灯片；以同一语义换语言、标签长度、图方向或风格，检查关系没有漂移。后续在可用的不同语义模型及图像模型上运行相同契约，不能将单次模型成功当成模型无关保证。

反馈应先定位失败所在层：消息不清需改变可见范围；归属错误需修正源投影或边界；路径难追需改变布局/路由；文字难读需改变密度/尺度；外观不协调才调整颜色、形状、字体、镜头与光照。针对病因修订，比继续追加一长串“漂亮、专业、顶会风格”更可检验。
