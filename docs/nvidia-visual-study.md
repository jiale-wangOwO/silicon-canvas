## 跨用途的设计原则

先确定图要帮助读者完成的任务。组织总览回答“有哪些层级、谁拥有谁、什么资源共享”；机制图回答“数据或控制经过哪里、发生了什么变化”；发布图回答“主角是什么、为什么值得关注”；路线图回答“各阶段在哪些维度演进”。这些任务需要不同构图，不能只靠替换配色区分。

组织图可以省略无关连线，但省略必须符合阅读范围。全芯片组织图不应冒充完整 datapath，模块清单也不等于机制解释。层级、数量和所有权仍然需要真实来源；full-chip 配置不能自动替代具体 SKU。

重复单元应采用稳定的局部模板，共享资源应显式放在重复模板外或贯穿其中。模板可以代表一组等价单元，但不能把不同所有权、不同容量或不同内部关系的实例合并成同一种结构。大块区域的视觉面积也不应被读者误认为精确芯片面积或容量比例。

对照图应保持共同对象的锚点、尺寸和排列稳定，把视觉变化集中在要解释的差异上。说明性引线、调用关系、实际数据路径和控制路径应有清晰区别。连线评价关注端点、方向、路径可跟踪性和是否存在无意义绕行；并非所有好图都使用相同的直角路由。

发布页和能力网格可以用较少的技术对象提高传播效率，但不能借此制造未经给定的参数、连接或性能结论。示意图、能力概览、组织图和实现事实图应保持范围诚实。历史发布路线图表达的是当时的计划，本笔记不核验后续兑现状态。

## 本轮落地与实际边界

当前共享核心已加入几项通用改进：需要追踪主要通路的系统总览保留真实 owner 内的主要数据路径，并增加按 owner 和路径组织的布局候选；纯组织概览与历史默认调用保持原有范围。已证实的重复单元采用更均衡的阵列。空间展示区分逻辑功能覆盖、保持装配的局部剖切、显式爆炸图和整体配同一对象的从属局部视图。局部剖切不再把各层折成一个库存清单，也不继承概念图的六区域、八关系裁剪预算。

自然语言中的剖切与爆炸否定分别处理；源规格保留用户给出的相对层次和装配状态。新增参考的三项文字特征进入现有 metadata-only 选择器，原图仍仅在本地。

早期构图试验使用 MCP 和内置 Image Gen。GPU 总览的语义抽取曾遗漏四个簇的独立归属，随后改用宿主 Agent 准备规格；因此不能据此宣称网页演示模型已稳定处理该例。构图结论进入共享规则，精选输出见[主页](../web/index.html#showcaseTitle)。旧试验页已从产品入口移除，不作为当前版本的质量认证。

这些结果检验了构图改进，不能证明所有场景已达到原厂发布质量。商业板卡的源投影仍会延后部分内部关系；实际位图还可能增加发光路径、误接标注或画出不准确的接触关系。本文中的同布局机制对照、时间与能力矩阵等观察也不等于本轮已实现相应的通用布局器。

## 原图的局限与权利

原厂图也不是任何场景下的审美模板。整芯片图在缩小后难以逐项读字，SM 内嵌原图只有 804×1357 像素；TMA 原图右侧保留了一个细小的截断字形。GTC 第 25 页的舞台指标被原编辑构图裁去一部分，不能据此复原完整系统参数；深底、极端字号差异和透视摄影也不应成为普通工程文档图的默认风格。
