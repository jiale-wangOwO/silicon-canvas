# 工程图的颜色、层级与字体

2026-10-18。此次研究针对 GPU 总览里颜色发闷、容器偏重的问题。以下是查看官方图后的观察及本轮采用的设计规则。默认 `paper` 风格已更新为“白皮书 · 明净”，并通过实际 GPU、Softmax 输出检查；当前结果与限制记录在文末。原厂的拓扑、实例数量和参数不作为其他芯片的模板。

三张最终本地参考均实际查看：两张 AMD 图从已有本地官方 PDF 准确裁出图形本体，以 300 dpi 渲染，不含邻近正文；Google 图核对官方页面和直接图片链接后复用已有原始 PNG，没有重复下载。当前 AMD 在线下载曾超时，因此本地 PDF 的 SHA 另行记录，不声称它与现在的远程文件逐字节相同。

本轮也实际查看了 Intel Xe2 发布材料第 5 页，以及已有 Intel Xe HPG、AMD 整芯片图。它们的组织方式有参考价值，但厚灰框、金属纹理、暗色卡片或倒影不适合作为这次默认工程风格的正面样板。Google 2017 TPU 论文的角色配色清晰，但粗大箭头和高饱和控制路径也不宜机械移植。选择参考应基于具体优点，不能因为来自大公司就整套照抄。

## 当前默认颜色

以下 HEX 是综合观察后的自有方案，未声称从厂商图精确取色。角色对应关系可以与原厂不同，但同一张图中必须保持一致。

| 用途 | 颜色 | 作用 |
| --- | --- | --- |
| 画布、接口与大多数容器 | `#FFFFFF` | 保持纸面清爽，避免整图发灰。 |
| 主要文字 | `#17324D` | 深蓝文字提供稳定对比，避免每块都使用黑色粗标题。 |
| 计算资源填色 | `#DCEAFF` | 明净浅蓝承担主要计算区域。 |
| 存储资源填色 | `#FFF0BE` | 暖金让共享缓存和存储带容易从计算阵列中被定位。 |
| 控制资源填色 | `#EEE5FF` | 淡紫保留控制角色差异，同时保持次要地位。 |
| 节点轮廓及普通连线 | `#6E8BAB` | 中等深度的蓝灰，清楚但不压过内容。 |
| 所有权容器轮廓 | `#BFCFE0` | 轻边界明确归属，不产生多层套盒的重量。 |

不要为每个模块添加一种新颜色。三个角色色已能建立差异；只有读者需要额外区分的事实才增加另一种视觉编码。填色应在白底上保留明确色相，避免通过反复加灰把所有角色变成相近的灰蓝、灰绿。颜色以外还要靠标签、形状、归属和位置表达含义。

## 颜色之外的共同规则

先安排真实的所有权、共享资源和主路径，再上颜色。父容器尽量白底或无填色，使用小标题加轻轮廓；真正需要识别的资源才填角色色。嵌套关系不能同时重复使用深色标题条、厚轮廓、阴影和大块底色来强调。

字体采用正常字宽的无衬线字形，以常规字重为主。层级主要来自位置、字号和少量半粗字，不用全大写窄体把每个标签都做成标题。短标签避免无意义断成三四行；详细参数可放在更小的次级文字中，但不能缩小到最终文档宽度下不可读。

等价单元使用一致的尺寸、间距和内部次序。共享缓存或互联可以成为清楚的贯穿带，但其面积不代表真实芯片面积。无需完整连线的组织总览应明确其范围；机制图则必须保留读者所需的端点和路径，不能靠少画线来掩盖关系丢失。

验收仍需看实际输出：文字是否清楚、角色色能否区分、容器是否抢眼、主关系是否连贯、技术事实是否完整。提示词写了这些要求，并不等于图片已经做到。

## 实现与实际输出

`catalog.json` 定义角色色，`reading_plan.py`、`publication_render.py` 与 `publication_brief.py` 将同一视觉规则用于结构参考及 Image Gen 提示词。`paper` 不再默认使用黑色标题条。图中文字也不再因为所属模块编号而强制展示重复说明；真正的容量、数值、条件和用户明确保留的原文仍保留。

两张新图均由当前源码 STDIO MCP 的 `silicon_prepare → 宿主源规格 → silicon_compile` 流程产生提示词，再原样交给内置 Image Gen。GPU 按工具要求附结构参考，算法图仅使用工具提示词；未重抽、追加修饰或编辑像素。两份原有源规格没有改变，便于区分视觉规则与技术内容的变化。65 项相关测试通过，测试覆盖规则一致性和参数文字保留，不能代替实际图片审查。

- [GPU 实际输出](../web/assets/engineering-style-20261018/gpu.png)：四计算簇与共享存储主路径可辨，灰绿底色与黑色标题块已移除。仍偏纵长、局部右侧留白较多，容器与节点有一处重复名称；生成模型的字重偏粗且浅色填充有轻微纹理。审查为 `partial`。
- [Softmax 实际输出](../web/assets/engineering-style-20261018/softmax.png)：主计算链及两处归约的八条依赖、公式与分组经肉眼检查完整，跨算法图的角色配色可辨。仍有轻微渐变，未检查论文单栏印刷尺寸；审查仅适用于本张图。

逐图审查与生成来源位于同目录的 `*-review.json` 和 `*-provenance.json`。当前证据支持视觉语言变得清楚，尚不支持所有场景都已达到商业白皮书品质。
